# WeeklyRun PRD Map (v0.10)

본 문서는 WeeklyRun PRD의 전체 내용을 요약하거나 축약하지 않는다.  
대신, **이 PRD를 읽고 구현하는 주체(특히 AI 에이전트)가  
무엇을 먼저 판단하고, 무엇을 나중에 판단해야 하는지**를 명확히 안내하기 위한
“읽기 가이드(Map)” 역할을 한다.

---

## 1. 제품의 본질

WeeklyRun은 회의 내용을 기록하는 도구가 아니다.  
주간업무록을 기준으로 **회의를 ‘진행’하고 ‘구조화’하는 AI 오케스트레이터**다.

- STT + 요약은 결과물 생성이다.
- WeeklyRun은 회의 도중 질문을 던지고, 흐름을 유지하며,
  회의 이후 더 완성도 높은 회의록을 만든다.

---

## 2. Phase 우선순위 개요

WeeklyRun 개발은 아래 순서를 **반드시 따른다**.

1. **P1-lite**  
   - 녹음 파일 업로드 기반
   - 주간업무록 참조 회의록 생성 파이프라인 검증
2. **P1-full**  
   - 실시간 회의 진행
   - 질문 트리 및 회의 오케스트레이션 UX 완성
3. **P2**  
   - 멀티 팀, 일반 회의, 잡담 필터링
4. **P3**  
   - 스트리밍 STT, 서버 배포, 슬라이드 생성

> ⚠️ P1-full은 P1-lite 완료 이후에만 착수한다.

---

## 3. 반드시 먼저 구현해야 하는 핵심 요소 (Do Not Skip)

아래 요소는 WeeklyRun의 정체성을 결정하며,
**UI 완성도나 애니메이션보다 항상 우선한다.**

- 주간업무록 파싱 규칙 및 구조
- STT 결과와 주간업무록 간 매칭 로직
- 회의록 생성 시 용어 교정 및 누락 감지 규칙
- Meeting / Recording / Minutes 상태 전이 규칙

---

## 4. 후순위 또는 단계적 고도화 대상

아래 항목은 기능적으로 중요하지만,
초기 완주 및 검증 단계에서는 단순화 또는 지연 가능하다.

- Weeky 캐릭터 애니메이션 디테일
- UI 전환 효과 및 시각적 마이크로 인터랙션
- 실시간 오디오 파형 시각화
- 고급 에디터 UX

---

## 5. 실패 허용 원칙

WeeklyRun은 AI 기반 시스템이므로,
아래 실패는 **허용되며 설계적으로 고려 대상**이다.

- STT 정확도 저하
- 실시간 회의 UX의 단순화
- 일부 자동 교정의 사용자 확인 필요 표시

단, 실패 이후 **재시도 및 복구 가능성**은 반드시 보장해야 한다.
