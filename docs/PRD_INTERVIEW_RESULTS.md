## 구현 방식 결정

### 비동기 처리

```
방식: FastAPI Background Tasks + Client Polling
사유: 단일 팀, 동시 처리량 적음, 추가 인프라 불필요
확장: P3에서 Worker로 분리 가능
```

### 누락 항목 매칭

```
방식: 하이브리드 (키워드 선검사 + AI 최종 판단)
```

### 복구 범위

```
브라우저 비정상 종료 시:
- 녹음 파일 복구
- 회의 진행 상태 복구
- 회의록 초안 복구 (30초 자동저장)
```

### Confluence 업로드 실패

```
1. 자동 재시도 (최대 3회)
2. 최종 실패 시 로컬 저장
3. 나중에 재업로드 가능
```

## 전역 상태 설계

P1-lite만이 아닌 **전체 시스템(P1~P2)을 고려**하여 초기 설계

```typescript
atoms/
├── team/           # 팀 정보 (P2 멀티팀 대비)
├── meeting/        # 회의 설정, 참석자, 진행 상태
├── recording/      # 녹음 상태, 파일, 진행률
├── stt/            # STT 처리 상태, 단계
├── minutes/        # 회의록 편집 상태, 저장 상태
├── confluence/     # Confluence 연동 상태
└── ui/             # 모달, 토스트, 로딩 상태
```
